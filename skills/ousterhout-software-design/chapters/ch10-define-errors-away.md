# 第 10 章：定义不存在的错误

## 核心思想

异常和特殊情况会扩散到所有调用者。最好的处理方式是重新定义正常语义，让错误不再发生；做不到时，在低层屏蔽或聚合；只有业务真正需要的错误才向上暴露。

## 引入的框架

- **定义错误不存在**：改变 API 语义，使原错误成为正常结果，如删除不存在项视为空操作。
- **异常屏蔽**：在最了解机制、且能代表统一结果的低层处理异常。
- **异常聚合**：多个细粒度错误使用同一恢复路径，减少处理器数量。
- **清晰终止**：对低概率、无法恢复且继续运行没有意义的错误，带诊断信息终止程序。
  - 何时使用：设计错误返回、异常边界或恢复协议时。
  - 如何做：判断上层是否需要该信息；不需要就定义掉/屏蔽，需要就保留清晰语义。

## 关键概念

- **错误重要性**：错误是否改变上层决策，决定是否必须暴露。
- **错误提升**：将多个小错误提升为一个已有的通用恢复事件。
- **特殊情况**：由额外状态和分支表示的非正常路径。

## 心智模型

异常处理器是接口的一部分；每增加一个可见异常，就增加所有调用者的认知和测试成本。

## 反模式

- **无条件吞异常**：网络消息丢失或对端故障被隐藏，调用者无法构建可靠行为。
- **每层各自恢复**：同一故障在多个层重复编写处理逻辑。

## 工作示例

文本选择始终存在，空区间代表不可见选择；复制空选择自然复制零字节，删除空选择自然保留原文。若磁盘内存耗尽且应用无法恢复，可统一由分配包装器记录诊断后终止。

## 关键结论

1. 先问错误信息是否对上层有价值。
2. 把处理器放到能捕获最多上下文的低层。
3. 不要把可靠性所需的错误静默掉；不要为不可恢复错误制造虚假恢复。
