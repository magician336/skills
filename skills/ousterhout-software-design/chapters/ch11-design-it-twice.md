# 第 11 章：设计它两次

## 核心思想

第一个可行设计往往受当前代码结构束缚。主动设计第二个甚至第三个明显不同的方案，能暴露隐藏假设，扩大设计空间并找到更深的接口。

## 引入的框架

- **两个候选方案**：不要只微调同一个结构；改变模块边界、数据表示或控制流。
  - 何时使用：公共 API、核心数据结构、跨服务协议和高成本重构。
  - 如何做：先分别写出职责、接口和主要调用，再按复杂性、可演化性和常见用例比较。
- **设计评估维度**：接口大小、隐藏知识、变化扩散、错误路径、常见用例的简洁度。

## 关键概念

- **设计空间**：所有可行结构及其权衡。
- **局部最优**：第一个顺手方案看似简单，却把复杂性转移给调用者。
- **方案对比**：用具体用例和未来变化来检验，而非靠审美。

## 心智模型

把第一次设计当作侦察，不是承诺。第二个方案的价值不只在于被采用，也在于揭示第一个方案的隐性成本。

## 反模式

- **只做命名替换**：两个“方案”实际上共享同一边界和依赖。
- **凭直觉选方案**：没有写出接口和调用路径就决定。

## 工作示例

为缓存设计 API 时，方案 A 暴露 `get/set/invalidate` 和 key 规则；方案 B 只提供带失效策略的 `fetch`。将典型调用、并发和后端替换需求写出来，往往会发现 B 隐藏更多机制，但若调用者需要批量失效，A 的显式能力更合适。

## 关键结论

1. 方案必须在结构上不同，才有比较价值。
2. 用调用者必须知道的知识量评价接口。
3. 对高影响边界，设计时间通常比后期迁移便宜。
