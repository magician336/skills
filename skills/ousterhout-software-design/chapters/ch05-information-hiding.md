# 第 5 章：信息隐藏（和泄漏）

## 核心思想

把设计决策封装在一个模块内部，既能简化接口，也能让变化局部化。若同一知识在多个模块出现，就形成信息泄漏；按时间顺序拆分尤其容易泄漏格式和协议知识。

## 引入的框架

- **信息隐藏**：隐藏数据结构、算法、格式、策略和关键假设，而不是只把字段声明为 private。
- **信息泄漏**：多个模块共享一个未集中表达的设计决策；接口泄漏最明显，后门泄漏更难发现。
- **时间分解**：按“先读、再改、再写”等执行顺序拆模块，导致不同阶段重复理解同一知识。
  - 何时使用：设计文件、协议或编译流水线组件时。
  - 如何做：按知识归属而不是执行时间分组；将解析和格式机制集中。

## 关键概念

- **部分隐藏**：少数高级用户需要的功能与常见接口隔离。
- **后门泄漏**：知识未写入接口，却被多个实现隐式依赖。
- **模块重组**：合并紧密相关模块，或提取真正抽象泄漏知识的模块。

## 心智模型

把每个设计决策看成“变化炸弹”：它应只有一个拆弹点。两个类都知道 HTTP 长度规则，就意味着未来格式变更要拆两次。

## 反模式

- **读类和解析类分离**：两者都必须理解协议格式。
- **getter/setter 假隐藏**：字段虽私有，语义仍被接口逐项暴露。

## 工作示例

HTTP 服务器若先由一个类读取请求字符串，再由另一个类解析，`Content-Length` 等规则会在两处出现。合并为一个负责读取和解析的深模块，调用者只需一次调用，格式知识也只有一个归属。

## 关键结论

1. 评审每个模块时列出它拥有的设计知识。
2. 同一知识跨模块出现时，先处理泄漏再优化局部代码。
3. 新模块只有在接口真正抽象细节时才有价值。
