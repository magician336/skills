# 第 6 章：通用模块更深入

## 核心思想

只为当前调用定制的模块往往很浅；面向一组合理用例设计的通用模块能隐藏更多机制。通用不等于把所有可能参数都暴露出来，而是找到稳定、简洁的抽象。

## 引入的框架

- **适度通用性**：设计接口时考虑多个现实用例，但拒绝没有证据支持的选项。
  - 何时使用：新类或库 API 尚未稳定时。
  - 如何做：列出已知用例的共同机制，选择最小的共同抽象；把少见策略封装在实现或独立扩展中。
- **三次设计**：在第一个可行方案之后，主动寻找不同结构的方案，比较哪个更深。
- **通用机制优先**：用一个可复用机制处理相关变化，少写特殊分支。

## 关键概念

- **特殊用途模块**：接口直接映射某一个调用点。
- **过度通用**：参数、回调和配置暴露了不必要的变化维度。
- **文本编辑器例子**：把选择、光标和文本表示设计成能覆盖空选择的通用机制。

## 心智模型

接口不是当前调用的截图，而是对机制的承诺；让调用者表达“想做什么”，不要让其拼装“内部怎么做”。

## 反模式

- **先写一个专用类，复制到第二处**：重复知识随后产生分叉。
- **万能配置对象**：所有潜在需求都变成公开字段，接口失去方向。

## 工作示例

文本编辑器可以把“没有选区”表示为空区间，而不是让每个复制、删除操作检查 `hasSelection`。同一个选择机制自然覆盖有选区和空选区，调用者接口更稳定。

## 关键结论

1. 从机制和不变量出发设计通用接口。
2. 用多个真实用例检验通用性，避免 speculative API。
3. 通用机制应减少特殊处理，而不是增加配置表面。
