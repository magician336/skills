# 第 17 章：一致性

## 核心思想

一致性降低认知负荷：一旦读者学会一个规则，就能迁移到更多位置。命名、参数顺序、错误语义、目录结构和层次方向都应尽量统一，并用工具保护约定。

## 引入的框架

- **一致性三要素**：相同概念用相同方式表达；相似操作具有相似接口；规则在边界处也可预测。
- **约定优于例外**：把常见行为设为默认，少数差异显式隔离。
  - 何时使用：设计团队 API、公共库和跨服务协议时。
  - 如何做：记录约定、提供模板/静态检查、迁移旧例外。
- **一致性与抽象**：统一不是复制实现；可以共享语义而保留不同层的内部机制。

## 关键概念

- **认知迁移**：已学规则在新位置直接复用。
- **例外成本**：每个特殊约定都需要额外记忆和文档。
- **自动化约束**：格式化、lint、类型和测试帮助约定持续存在。

## 心智模型

一致性像压缩算法：重复规则只需学习一次；例外越多，压缩率越低，理解成本越高。

## 反模式

- **个人风格优先**：同一仓库中使用多套词汇和接口顺序。
- **只写规范不执行**：约定没有检查器、模板或评审门槛。

## 工作示例

如果所有异步 API 都以 `Context` 开头、错误作为最后返回值，新增方法应遵循同样顺序；若确有不同生命周期，另建明确命名的接口，而不是静默改变规则。

## 关键结论

1. 优先统一高频、跨模块的表达。
2. 用自动化减少对记忆和人工评审的依赖。
3. 一致性服务于可推断性，明显错误的旧约定应计划迁移。
