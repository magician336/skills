# 架构健康度审查

交付物是「**哪里做得不够好、应该怎么重构**」，不是健康项清单，也不是改造方案本身。评分必须由结构性缺陷和可复核证据驱动；测试通过、文档齐全、CI 绿只能证明某条路径被验证过，不能替代模块深度、信息隐藏或变化放大的判断。

## Inputs to collect

- 审查范围（哪些模块 / 目录 / 子系统）与阶段（设计期 / 实现后 / 合并前）；
- 当前 SHA；
- 项目的领域词汇表与架构决策记录（`CONTEXT.md`、`docs/adr/` 一类）。先读这些：它们定义了「好」的形状，也记录了**不该重新讨论**的决策。

如果项目自带健康度评分协议（评分维度、权重、基线、等级），**以它为准**，不要另起一套并行口径；只把下面的纪律（先找缺陷再打分、反通胀门槛、置信度、阻断风险）套上去。

## Procedure

### 1. 先找缺陷，再打分

对每个维度，先用证据描述结构性不足，而不是先给分。必答四问：

1. 哪个变化会牵动最多模块？为什么这是**变化放大**而不是单纯工作量？
2. 哪条设计知识（权限、状态、格式、并发、恢复、供应商策略）泄漏到了多个模块？
3. 哪个接口只是转发参数或暴露内部数据结构，本该合并、下沉或变深？
4. 哪些特殊情况可以被统一语义、空对象、聚合错误或单一恢复机制消除？

### 2. 按固定锚点打分

0–5 的锚点与默认维度见 `references/scoring-rubric.md`。关键点：**3/5 是「能工作但有明显债务」，不是健康默认值**。

每项记录：分数、证据路径、验证命令、置信度、模块级重构方向。不要用文件数、代码行数、测试数量代替复杂性判断。

### 3. 反通胀门槛

出现以下任一情形，**不得给 4–5 分**：

- 只有泛泛描述，没定位到具体模块；
- 只有单元测试通过，没有边界或调用路径证据；
- 设计意图与真实代码不一致（按代码评，不按意图评）；
- 同一知识在两层以上重复表达；
- 大量 pass-through 方法、特殊分支或隐藏副作用；
- 关键失败只能靠重跑或人工修复。

反过来，**低分不是失败测试的同义词**：低分表示代码在变化、理解或恢复上已经产生结构性成本。

### 4. 写重构方向

每条低分项至少给一条可执行建议，格式固定：

`模块/边界 → 结构问题 → 重构动作 → 预期减少的变化放大或认知负荷 → 回归门槛`

重构动作只能是：模块合并 / 拆分、职责下沉、端口收窄、策略集中、状态机归属、错误语义统一、消除透传。「补测试」「加强文档」「重跑 CI」不能当重构动作——测试是证据和回归门槛，只有当测试失败暴露结构缺陷或阻塞安全重构时，才可以进最高优先级。

### 5. 排序与阻断

最高优先级按**复杂性降低收益**排序：变化放大范围 × 变化频率 × 边界关键性。没有定位到模块和重构动作的项，不得排进最高优先级。

任一关键维度 < 2/5 → 单独列为**阻断风险**，不能被总分掩盖。

### 6. 标置信度

- `A`：主要结论由自动化测试、CI 或可复现运行结果支持；
- `B`：主要结论由代码抽样、文档与部分自动验证支持；
- `C`：主要依赖设计意图、个人判断或未验证假设。

关键维度缺证据时整体置信度最多 `B`；多个关键维度缺证据时为 `C`。

「未知的未知」不直接打分，改用未知发现速度、失败诊断、可观测性、回退能力、关键假设的验证程度来评估。

## Output contract

1. 总体评分 /100 与置信度（项目有既定评分对象与权重时按项目口径报，不要自造指标）；
2. 维度分项表：维度 | 分数 | 证据 | 置信度 | 与上次差值 | 改进动作；
3. 低分项的结构性不足与重构方向（按上面的固定格式）；
4. 按复杂性降低收益排序的最高优先级动作；
5. 阻断风险（关键维度 < 2/5）；
6. SHA、范围、验证命令、未覆盖风险。

没跑的验证写 `NOT RUN` 并附确切命令，不要写成通过。

## Failure handling

- 证据不足 → 降低**置信度**而不是降低**分数**；两者是不同轴，混为一谈会把「没查清」写成「结构没问题」。
- 项目无领域词汇表 → 用代码里的既有命名描述，不要发明术语。
- 与既有架构决策冲突 → 标出冲突并说明摩擦是否真实到值得重开该决策；不要罗列理论上被禁的重构。
- 结论与团队既有结论冲突 → 给出证据差异在哪，不要靠语气压过去。
- 范围过大无法逐模块评估 → 明确声明取样范围与未覆盖部分，置信度不高于 `B`。

## Examples

输入：「这套代码结构有什么问题？后续加需求会不会越来越难？」

输出：评分 62/100，置信度 B；「权限判定」这条知识在 3 个模块重复表达（变化放大 × 高频 × 关键边界）→ 最高优先级动作：权限判定下沉到单一策略模块，回归门槛是三处调用点收敛为一次；`演化式设计` 维度 1/5 → 阻断风险：新增能力必须同时改 4 个文件。
